Cloudflare подготовит отдельную копию серверного проекта в GitHub, создаст D1 и выполнит миграции. В форме задайте BAZAR_OWNER_PASSWORD (минимум 16 символов); логин кабинета owner@bazar.local. Если имя репозитория занято, используйте Bazar-server. Четыре GitHub Secrets для этого варианта не нужны. После успешного запуска передайте исполнителю публичный Worker URL для проверки и привязки прежнего GitHub-сайта. Удалённая проверка этой формы ещё не выполнена.

# БАЗАР · Բազար · ბაზარი

Отдельный магазин овощей и фруктов. Армянский, русский, грузинский; города Ахалкалаки и Тбилиси. Учебный каталог: 49 товаров на город, два поставщика. Цены и остатки тестовые.

## Что реализовано

Светлая мобильная витрина, поиск, категории, наборы, сохранение корзины отдельно для города; оформление на сервере, окна выдачи/доставки; резерв склада; поставщики и курьеры с ограниченными правами; подтверждение звонка; наличие и отсутствие; согласование замены покупателем; вес по каждому товару; готовность всех частей; доставка; отдельный журнал подтверждённых оплат; расходы и расчёт чистого дохода; приглашения сотрудникам; журнал действий и очередь событий. Новые города, поставщиков, категории и товары можно создавать из кабинета.

Повторные команды и оформление защищены ключами идемпотентности. Изменения выполняются в D1 batch с проверкой версий и остатков. Исходные условия заказа хранятся отдельно от текущих позиций. Стоимость на сервере, деньги в целых тетри, вес нетто в граммах. Неизвестная себестоимость остаётся неизвестной.

## Вес

Обычный развес: до ±10%, но не более 200 г в каждую сторону. Для отдельных товаров предел меньше. Целые арбузы, дыни, тыквы и кочаны выбирают по диапазону веса **каждого плода**, без дополнительных ±10%. Поштучные товары, пучки и упаковки имеют фиксированное количество. В пределах принятых условий новое согласование не нужно; за пределами и при замене требуется согласие. Оплата по фактическому количеству.

Правила: [docs/WEIGHT_RULES_RU.md](docs/WEIGHT_RULES_RU.md). Ранее опубликованный пакет [weight-rules](weight-rules) сохранён.

## Запуск и проверка

Node.js 24 или новее:

```sh
npm ci
npm test
npm run build
npm run dev
```

Локально http://localhost:5174. Данные в игнорируемой `.runtime/bazar.sqlite`; доступ владельца генерируется в `.runtime/local-access.json` (не отправлять в GitHub). Демо-данные создаются только в пустой базе. Миграции нормализованной схемы в `migrations/`.

## Развёртывание на собственном Cloudflare

Создать **отдельную** D1 `bazar-db`, внести её настоящий ID в `wrangler.jsonc`, применить `npx wrangler d1 migrations apply bazar-db --remote` и развернуть `npx wrangler deploy`. Исходный `worker.mjs` намеренно не доверяет заголовкам идентификации сторонних платформ. Первый владелец создаётся доверенным серверным инструментом с PBKDF2-паролем; публичной регистрации владельца нет. Не включать боевой приём заказов до настройки реального каталога, городов, слотов и доступа владельца.

Закрытый предпросмотр использует отдельный адаптер `sites.mjs` и выделенную D1. Владелец определяется платформой только в этом **закрытом** варианте. `/internal/self-test` проводит синтетическую проверку и существует лишь в этом адаптере; перед публичным развёртыванием используется `worker.mjs`, без него.

## Ограничения

Боты, рассылки, Google Таблицы и эквайринг отключены. События сохраняются, отправки не имитируются. Подготовленная очередь ещё не является подключённой интеграцией. Нет загрузки чеков и обработки возвратов; сумма поступления подтверждается отдельным действием владельца. Порог 10% проверяется при закрытии расчёта с явно введёнными расходами; это контроль, а не гарантия будущей прибыли. Акции, резерв по партиям/срокам годности и полная бухгалтерия требуют отдельного продолжения.

GitHub Pages может показывать статический каталог и корзину (`node tools/build-pages.mjs` → `dist-pages/`), но не выполняет Worker и не принимает заказы. Работающий закрытый предпросмотр — отдельное развёртывание с сервером.
