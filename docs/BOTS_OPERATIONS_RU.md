## Что перенесено и адаптировано

| Механизм эталона | Реализация Базара |
| --- | --- |
| Общая группа курьеров, личность нажавшего | Telegram ID связывается с существующей учётной записью; группа не даёт прав сама по себе |
| Первый курьер берёт заказ | Общая серверная команда, версия заказа, атомарный batch; второй курьер не получает управление |
| Звонок перед сборкой | Поставщики получают свои позиции с запретом сборки до подтверждения |
| Несколько поставщиков | Свои позиции и статусы каждой части; готовность всего заказа только после всех частей |
| Изменение заказа | Курьер — назначенный заказ, поставщик — свои позиции; согласие покупателя на замены/выход за весовой допуск |
| Живые сообщения | Сохраняются chat_id/message_id; новое состояние редактирует существующее сообщение |
| Доставка и деньги | Доставка отдельно; курьер сообщает сумму/метод, владелец подтверждает или отклоняет |
| Смены | /shift DAY, /shift HOURS 09:00 18:00, /shift OFF; ответ фиксирован на день, /leave — экстренный уход |
| Деньги у курьера | Сообщённые наличные, проверка, передача владельцу с ограничением суммы и идемпотентностью |
| Реферальная акция | Первый пригласивший; нельзя пригласить себя/взаимно; одна награда за друга после доставки И проверки оплаты |
| Кампания и срок баллов | Процент, дата окончания, срок баллов; FIFO расходование, журнал; выдача награды записывается владельцем |
| Акции | Серверная скидка на выбранные товары, город, даты, три языка; скидки не складываются |
| Вечерний базар | Отдельный раздел и временное окно по Asia/Tbilisi; принятый заказ сохраняет цену |

Программа рекомендаций выключена до настройки владельцем; никаких скопированных 50% вознаграждения или вымышленных прибылей. Баллы не списываются автоматически в корзине: владелец отдельно фиксирует фактически выданное поощрение. Такая запись не меняет цену заказа и не подтверждает поступление денег.

## Админка

В кабинет добавлены Сегодня, Диспетчер, Замены, Курьеры, Касса курьеров, Telegram, Акции, Вечерний базар, Реферальная программа, Клиенты, Платежи и Журнал действий. Существующие Заказы, Товары/остатки, Поставщики, Сотрудники, Финансы сохраняются. Пустые состояния показывают отсутствие записей; вымышленные данные и неработающие разделы не добавлялись.

Это расширение существующей админки, не полная копия всех разделов «Пивки». Автоматические утренние опросы смен, зарплата за поездку, чат поддержки с темами, ежедневная сверка поставщиков и их выплаты из Telegram ещё не перенесены. Google Sheets по-прежнему не подключены.

## Подключение бота

Один выделенный Telegram-бот обслуживает все роли. Нельзя переиспользовать токен ТЖВЖИКа или «Пивки»: setWebhook переключает единственную точку доставки обновлений у бота.

1. Развернуть ветку с этим изменением, применив миграции 0003 и 0004 через `npm run deploy` (скрипт сначала применяет миграции). База существующая, данные не удаляются.
2. В Cloudflare Worker `bazar-demo` сохранить Secret `TELEGRAM_BOT_TOKEN` и отдельный случайный `TELEGRAM_WEBHOOK_SECRET` (32–256 букв/цифр/_/-).
3. Проверить `/api/health`: operationsVersion=1, database=true, telegram=true. telegram=true означает наличие конфигурации, а не доказанную доставку.
4. В кабинете Telegram нажать регистрацию webhook. Альтернатива для авторизованного Wrangler: `node --use-env-proxy tools/connect-telegram.mjs https://bazar-demo.xugushik.workers.dev` читает только игнорируемый `.runtime/telegram-secrets.json`, проверяет авторизацию/версию сервера, записывает Secret и проверяет webhook; токены не выводит.
5. Владелец создаёт привязку своего личного чата и каждой группы. Для группы: добавить бота, назначить администратором, отправить `/connect <одноразовый код>`. Код действует 15 минут; подтвердить может администратор группы.
6. Каждый сотрудник принимает отдельное приглашение в учётную запись, затем связывает «Мой Telegram» из своего кабинета. Случайный участник группы не получает права по её факту.
7. После покупки покупатель связывает Telegram одноразовой ссылкой из защищённой карточки своего заказа; ключ заказа не помещается в URL Telegram.

Проверка связи и регистрация webhook выполняются только явными действиями владельца. Само сохранение кода не посылает реальным людям сообщения. В тестах Telegram полностью подменён локальным адаптером; реальных клиентов и денег нет.

## Надёжность и ограничения

Обновления Telegram проверяются отдельным webhook secret, update_id хранится для дедупликации. Кнопка содержит непрозрачный идентификатор, а действие, версия и чат проверяются на сервере. Действия входят в тот же журнал заказов, что и админка.

Уведомления ставятся в tg_jobs триггером внутри той же транзакции, что событие заказа. Доставка внешнему сервису идёт после сохранения; отказ Telegram не откатывает заказ. Очередь объединяет изменения для одной пары заказ/чат и повторяет временные ошибки. Запасной cron каждые 2 минуты обрабатывает маленькие пачки по 2 сообщения; при большой очереди полное обновление всех чатов не мгновенно. Этот режим выбран без подключения платных Cloudflare Queues. Админка показывает ожидание и ошибки.

Если первая sendMessage могла пройти, но ответ потерялся, запись помечается ambiguous и автоматически не повторяется: владелец проверяет группу и разрешает повтор. Это честное ограничение Telegram: API sendMessage не предоставляет идемпотентный ключ. Редактирования используют сохранённый message_id. Публичная группа курьеров не получает телефон/адрес; полная карточка приходит только назначенному курьеру в связанный личный чат.

Секреты — только Cloudflare Secrets/закрытый игнорируемый файл. Не публиковать токены в GitHub/README/PR, не выводить URL Telegram API в ошибки.

## Проверки

54 автоматических теста, в том числе сценарий двух поставщиков через смоделированные Telegram updates: принятие по Telegram ID, запрет постороннему/второму курьеру, звонок, наличие/отсутствие, согласование изменения покупателем, готовность, получение, выезд, доставка, отдельная проверка оплаты, повторы webhook и редактирование сообщений. Отдельно: отказ/429 Telegram, неоднозначная первая отправка, касса, смены, акции, границы расписания, история цены, реферальное начисление/срок/повтор/выдача.

Проверки используют SQLite-адаптер D1 и Telegram mock. Они не доказывают прохождение полного цикла в реальных группах Telegram. Визуальная проверка локального интерфейса была заблокирована разрешениями браузера. Публичное развёртывание этого обновления требует авторизованного Cloudflare; main не изменяется автоматически.
