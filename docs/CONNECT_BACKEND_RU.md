# Подключение настоящего сервера Базара

Подготовлено 16.10.2026. Реального развёртывания в аккаунте владельца пока нет: Wrangler не авторизован, браузер Cloudflare вернул `Unable to sign in` при выбранном входе через GitHub. Тестов 41/41; локальный интеграционный тест выполняет запросы от Origin GitHub к Worker, сохраняет заказ в совместимой SQLite/D1 базе, проверяет повтор команды и чтение по покупательскому ключу. Это не проверка настоящего удалённого Cloudflare.

## Схема

Покупатель открывает https://xugushik-source.github.io/Bazar/ . public/deployment.json содержит HTTPS origin отдельного Worker. Публичные запросы каталога, расчёта, заказа и просмотра собственного заказа разрешены только с origin https://xugushik-source.github.io . CORS не передаёт cookies и не разрешает административные маршруты. По кнопке кабинета сотрудник переходит на сам Worker, где сессия работает на своём origin с HttpOnly/SameSite=Strict cookie. Роли на сервере сохраняются.

CORS не является средством аутентификации: обладатель покупательского ключа может читать свой заказ; сотрудники входят отдельно. Секретный ключ не попадает в URL. GitHub Pages разных репозиториев одного аккаунта имеют общий origin — разрешение нельзя ограничить URL-путём /Bazar/ через Origin.

## После авторизации — действия исполнителя

1. Проверить аккаунт и отсутствие конфликта имени bazar-demo. Использовать только отдельную базу bazar-db. Не менять ТЖВЖИК или другие Workers.
2. Создать D1 при отсутствии: `npx wrangler d1 create bazar-db`. Подставить реально возвращённый database_id в wrangler.jsonc; это идентификатор ресурса, не секрет. Не создавать повторно уже существующую базу.
3. Для защищённого кабинета владельца задать BAZAR_OWNER_EMAIL и BAZAR_OWNER_PASSWORD через секреты Cloudflare. Пароль выбирает владелец, не менее 16 символов; не записывать в GitHub/документы/чат. src/cloudflare.mjs создаёт владельца однократно, хранит только PBKDF2 hash и никогда не сбрасывает существующий пароль. После первой инициализации секреты можно удалить. Без этих секретов сервер покупателей работает, но владелец автоматически не создаётся.
4. `npm ci`, `npm test`, `npm run deploy`. Deploy применяет только миграции отдельной базы DB, затем развёртывает src/cloudflare.mjs с текущими статическими файлами. Начальные данные создаются идемпотентно на первом API-запросе. Цены/остатки пока явно тестовые.
5. Проверить реально выданный HTTPS Worker URL и `/api/health`. Команда `npm run connect:api -- <реальный HTTPS origin Worker>` проверяет здоровье, отсутствие данных сотрудника в публичном bootstrap, каталог и CORS/preflight. Только после успеха она записывает public/deployment.json. Она не принимает пароли или API-токены.
6. `npm run build:pages`; сохранить исходники в feature/bazar-store, обновить public/deployment.json и клиентские файлы в gh-pages. Основную ветку не менять. Проверить в браузере полный путь GitHub → quote → заказ → чтение из D1 → кабинет владельца.

Последний пункт не выполнен: реального Worker origin нет. Никакая ссылка не выдумывалась, пустая конфигурация сохраняет текущий каталог в рабочем состоянии. DNS, эквайринг, Telegram и Google не затрагиваются.

Официальные инструкции: https://developers.cloudflare.com/d1/wrangler-commands/ и https://developers.cloudflare.com/workers/wrangler/commands/general/ .

## Альтернатива браузерному входу: GitHub Actions

Ветка feature/bazar-store содержит `.github/workflows/cloudflare.yml` и `tools/deploy-ci.mjs`. Сценарий запускается при изменении этих файлов в рабочей ветке; после добавления секретов исполнитель повторно запускает неудачный job через GitHub. Не нужно переносить workflow в main ради кнопки workflow_dispatch.

Разово нужны Repository Actions secrets:
- CLOUDFLARE_API_TOKEN: токен выбранного аккаунта с Account / Workers Scripts / Edit и Account / D1 / Edit. Не Global API Key и не токен с правами DNS/биллинга. Токен имеет доступ к Workers/D1 выбранного аккаунта; при строгом требовании изоляции используйте отдельный аккаунт Базара. После работы его можно отозвать.
- CLOUDFLARE_ACCOUNT_ID: идентификатор нужного аккаунта.
- BAZAR_OWNER_EMAIL: почта для входа владельца в кабинет Базара.
- BAZAR_OWNER_PASSWORD: выбранный владельцем пароль кабинета, минимум 16 символов, не пароль Cloudflare.

Все значения вводит владелец прямо в защищённые Secrets GitHub; не присылать их в чат и не помещать в исходники. Сценарий проверяет наличие всех значений до обращений к Cloudflare, ищет только bazar-db (повторно использует её, не пересоздаёт), применяет миграции, развёртывает только bazar-demo, проверяет полученный Worker URL, CORS и каталог. Секреты владельца передаются Wrangler через временный файл с правами 600 и удаляются; в артефакт входят только публичный API origin и идентификатор базы. Код не меняет DNS и не обращается к платежам.

После успешного job исполнитель забирает backend-connection, обновляет deployment.json в исходной и gh-pages ветках, проверяет заказ на GitHub-сайте. До такого успеха реальное развёртывание не подтверждено. Текущая проверка сценария ограничена синтаксисом, отсутствием записи при недостающих секретах и 41 тестом приложения. Полный CI deploy пока не проверен из-за отсутствия секретов.

Официальный способ: https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/ .

## Упрощённый запуск через Cloudflare Deploy
Кнопка в README использует официальный Deploy to Cloudflare. Платформа копирует серверный проект в отдельный репозиторий (при конфликте имени выбрать Bazar-server), сама создаёт D1 и записывает настоящие идентификаторы. Миграции входят в deploy-команду. В шаблоне один обязательный секрет BAZAR_OWNER_PASSWORD (минимум 16 символов), логин owner@bazar.local задан несекретной переменной. Не надо создавать API-токен или четыре GitHub Secrets. Могут потребоваться обычный вход в Cloudflare и подтверждение GitHub-интеграции. Число кликов и успех формы не проверены в аккаунте; автоматический браузерный вход заблокирован. После успешного Deploy требуется проверить реально выданный URL и привязать его через connect:api к прежнему GitHub-сайту. Не заявлять, что магазин уже принимает заказы, до этих проверок.
