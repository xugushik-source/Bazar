# Копия заказов в Google Таблицы

D1 остаётся основным хранилищем. Таблица — резервная копия: каждый заказ записывается строкой и обновляется при каждом изменении.

## Включение (решение владельца; сейчас в README написано «Google Таблицы отключены» — это надо обновить)

Секреты Cloudflare (в репозиторий не кладутся):
- `GOOGLE_SHEETS_ID` — id таблицы;
- `GOOGLE_SERVICE_ACCOUNT_JSON` — JSON ключа сервисного аккаунта; таблица открыта этому аккаунту на редактирование;
- `GOOGLE_SHEET_NAME` — имя листа (по умолчанию «Заказы»), необязательно.

Без этих секретов ничего не отправляется, и статус честно показывает «не подключено».

## Что попадает в таблицу

Номер заказа, дата и время, статус, оплата, способ, программа (если заказ из абонемента), получатель, телефон, адрес, товары с количеством, суммы в тетри, версия и время обновления.
**В таблице персональные данные** (имя, телефон, адрес). Текст согласия (`src/legal.mjs`) должен прямо называть Google как место хранения — это до включения.

## Надёжность

- Строка на заказ, номер строки запоминается; изменение заказа обновляет ту же строку.
- Если запрос на добавление строки пропал без ответа, строка могла появиться. Такой случай не повторяется автоматически (статус ERROR, APPEND_UNKNOWN): оператор проверяет таблицу вручную.
- Ошибка до записи (например, 400) — повтор на следующем запуске.
- Статус для владельца: `POST /api/manage/sheet-sync`.

Файлы: `migrations/0114_sheet_sync.sql`, `src/sheets-sync.mjs`, `tests/sheets-sync.test.mjs` (7 тестов, включая проверку подписи JWT настоящим ключом).

Не проверено на настоящем Google: тесты используют фейковый API. Нужен реальный прогон с тестовой таблицей.
