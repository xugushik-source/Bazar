# Уведомления поставщикам и курьерам — «Забота о близких»

Клиенту уведомления не отправляются: он заказал и забыл, доставка видна в его кабинете.

| Кому | Когда | Что |
|---|---|---|
| Поставщику (чат SUPPLIER) | 19:00 накануне | что подготовить на завтра: его товары, суммы по всем заказам дня |
| Поставщику | 09:00 в день | что передать сегодня (итоговый список) |
| Курьерской группе (чат DRIVER) | 19:00 накануне | полный список доставок на завтра: время, адрес, получатель, телефон |
| Курьерской группе | 09:00 в день | список на сегодня |
| Личному чату курьера (PERSONAL) | 09:00 | его назначенные заказы на сегодня |

Курьерская группа должна состоять только из курьеров и владельца: там адреса и телефоны получателей.

- Один dedup_key на сообщение: повторный запуск cron дубля не создаёт.
- Нет чата или Telegram выключен → задача оператору (`GET /api/manage/subscriptions/tasks`), имитации отправки нет.
- Ошибка до доставки — повтор с паузой. Неизвестный исход — AMBIGUOUS, без автоповтора.
- Тексты ru/hy/ka; hy/ka — черновики, нужна проверка носителем.

Поставщик должен быть привязан к Telegram (`tg_links`, kind=SUPPLIER, ref_id = id поставщика).
Ошибка, найденная при тестах: `INSERT OR IGNORE` скрывал нарушение CHECK, и уведомления поставщику молча не создавались. Теперь используется `ON CONFLICT DO NOTHING`.
