# Телефонное оформление — черновик реализации

Основа: feature/bazar-store. Изменения: feature/bazar-phone-operator.
Production не публиковался, удалённая D1 не изменялась.

## Как пользоваться после применения миграции в тестовой среде

Войти владельцем → Кабинет → «Принять заказ по телефону».
Ввести данные покупателя, найти товары (по всем трём локализованным названиям), добавить их и изменить граммы/количество/диапазон целых тушек. Выбрать дату, доступное время и способ оплаты. Серверный расчёт показывает оценку и максимальную сумму. Согласие на правила веса и обработку данных нужно получить от покупателя и отметить явно.
«Сохранить» сохраняет незавершённый черновик в той же D1; список рядом загружает последние 30 черновиков владельца в этом городе. Данные до нажатия «Сохранить» живут только в памяти текущей страницы.
«Обновить» под телефоном ищет историю в последних 1000 заказов города; «Повторить заказ» переносит состав и адрес, после чего общий API заново проверяет ассортимент, цены и остатки. Это не доступ к корзине покупателя по телефону.
«Оформить заказ» вызывает защищённую оболочку над createOrder. После неопределённого ответа сети повторяется ровно тот же payload и ключ идемпотентности; изменения формы блокируются. После определённой ошибки форму можно исправить.
Создание не подтверждает разговор. Подтверждение пока выполняется существующей кнопкой «Звонок подтверждён» в общей карточке заказа.

## Интеграция

/api/manage/phone/create доступен только владельцу и защищён общей сессией/CSRF. В createOrder добавлен доверенный серверный контекст сотрудника. Общие проверки, резервирование товаров/слотов, quotes, номер BZ, D1 orders/order_lines/order_groups, CREATED и outbox остаются прежними. В orders.source сохраняется PHONE_OPERATOR, в CREATED — сотрудник и источник. Публичный endpoint не может передать этот контекст. Платёж остаётся UNPAID, confirmed=false. Существующие отчёты и карточки читают те же таблицы. События сохранения черновика и просмотра истории попадают в operations_audit. Миграция 0111 добавляет только phone_drafts, без отдельной базы или очереди.

## Проверено

npm test: успешно, 12 тестовых файлов. npm run build: успешно, wrangler deploy --dry-run, без публикации.
Отдельно без BAZAR_IGNORE_ORDER_HOURS: node --test --test-name-pattern='orders only 09:00' tests/system.test.mjs — успешно.
Новые проверки: одинаковые суммы, максимумы, quotes, статусы, два поставщика, весовые позиции, отсутствие автоматического подтверждения/оплаты, единый outbox, идемпотентный повтор, отклонение неверной цены и недоступного товара, ограничения доступа, версии черновика, отсутствие резервов/заказов при сохранении черновика.
Остальные этапы сборки, проверки, изменения веса, оплаты и Telegram покрыты существующими тестами. Реальных отправок и финансовых действий не выполнялось.
Это SQLite-совместимость, не hosted D1. Браузерная проверка на iPhone, реальное отключение сети и полный путь телефонного заказа через Telegram не проверены.

## Не реализовано — критерий полной готовности ещё не выполнен

1. Выделенные права уполномоченных сотрудников и выдача/отзыв этих прав владельцем. Пока только владелец.
2. Безопасная передача начатой покупателем корзины (режим Б) и защищённая ссылка покупателю на черновик (режим В).
3. Завтрашнее оформление вне рабочих часов и автоматический отложенный запуск. Общие ограничения времени сохранены. Сейчас существующее подтверждение немедленно запускает сборку и открывает заказ курьерам, поэтому подтверждать будущий заказ этим способом заранее нельзя. Нужен согласованный с общим расписанием механизм отложенного запуска и его тесты.
4. Явная запись результата первоначального разговора прямо на экране оператора. Пока используется обычная карточка и обычное подтверждение; автоматического подтверждения нет.
5. Полная история покупателя за пределами последних 1000 заказов города и нормализованный индекс телефона.
6. Сохранённый черновик после оформления пока остаётся в списке; повтор с тем же ключом не создаёт новый заказ, но управление завершёнными черновиками нужно доработать.

PR должен оставаться Draft до реализации этих пунктов и проверки полного пользовательского пути. Публикация требует отдельного разрешения владельца.
